序列與 Transformer：讓模型「看懂」順序

上一站的圖片是「空間上」有關係，這站的資料是「順序上」有關係——例如一句話、一段逐月的銷售數字。

為什麼「順序」是另一種麻煩

「我 吃 蘋果」跟「蘋果 吃 我」用的是同一組字，順序不同，意思完全相反。線性層跟上一站的卷積層，天生都不理解「順序」這件事——它們看到的就是一堆數字，不知道「這個數字排在前面那個數字後面」有沒有意義。要處理這種「前後有關係」的資料，需要專門設計的架構。

解法的名字：RNN 到 Transformer 的演進

最早的解法叫 RNN（循環神經網路）：一個數字接一個數字依序讀進去，每讀一個就更新一次「記憶」，有點像「邊讀邊在心裡累積印象」。缺點是「序列太長時，前面讀到的東西容易被忘掉」，而且因為是依序處理，沒辦法平行加速計算。Transformer（這也是這整個 AI 浪潮裡最重要的架構之一，AI Agent 學習地圖裡 LLM 那站提過的「大腦」本體用的就是它）換了一套做法：用 注意力機制（Attention） 讓每個位置可以直接「回頭看」序列裡任何其他位置，不用依序一步步傳遞記憶，既能記得更久遠的關係，又能平行計算、訓練速度快得多。

之後查資料時，會遇到的關鍵字

名詞在做什麼對應函式庫/類別

深入機制（進階，可選讀）

想知道 Attention 到底在「注意」什麼、Transformer 少了 RNN 那種「依序讀」要怎麼還知道誰在前面，這裡多講一點。

1. Attention 在算什麼：每個字都「問」一次「誰跟我有關」

想像你在幫一句話做翻譯，要決定某個字該怎麼翻時，你不會只看這個字本身，而是回頭掃過整句話，問自己：「這句話裡，哪幾個字跟我現在這個字最有關係？」——離得近的字不一定重要，離得遠的字也可能超相關（例如代名詞「它」指的是誰，常常要往回看好幾個字）。Attention 幫句子裡 每一個字 都問了一次這個問題：拿自己（Query，「我想知道什麼」）去跟句子裡每個字（Key，「我能提供什麼線索」）比對相關程度，算出一組分數，再用這組分數決定要把每個字的內容（Value，「實際的意思」）「聽」多大聲——相關的字權重高、不相關的字權重低，加權混合之後，就是這個字在這句話脈絡下真正的意思。Query、Key、Value 三個都來自同一句話時，這個動作就叫 自注意力（Self-Attention）。

2. 位置編碼：拿掉了「依序讀」，怎麼還知道誰在前面

RNN 天生理解順序，因為它本來就是一個字接一個字依序讀進去的——順序本身就寫在「讀到的時間點」裡。Transformer 為了能平行計算，把這個「依序讀」的限制整個拿掉，所有字是同時丟進去處理的——代價是它完全不知道「誰在前面、誰在後面」：「我 吃 蘋果」跟「蘋果 吃 我」如果不做額外處理，在它眼裡長得會一模一樣。解法是在每個字的向量上，額外疊加一組跟位置有關的數字（位置編碼，Positional Encoding，通常用不同頻率的 sin／cos 波形算出來），讓「這是第一個字」「這是第五個字」這種資訊被偷偷夾帶進每個字的表示裡，模型才有辦法分辨順序。

3. 兩套框架怎麼寫最小的 Attention

PyTorch
import torch
import torch.nn as nn

attn = nn.MultiheadAttention(embed_dim=8, num_heads=2, batch_first=True)

x = torch.rand(1, 5, 8)  # 1句話、5個字、每個字用8個數字表示
out, weights = attn(x, x, x)  # Query=Key=Value=x，就是自注意力

print(out.shape)  # torch.Size([1, 5, 8])
print(weights.shape)  # torch.Size([1, 5, 5])　每個字對每個字的關注程度
TensorFlow
import tensorflow as tf
from tensorflow.keras import layers

attn = layers.MultiHeadAttention(num_heads=2, key_dim=4)

x = tf.random.uniform((1, 5, 8))
out = attn(query=x, key=x, value=x)  # 一樣是自注意力

print(out.shape)  # (1, 5, 8)
